## Purpose

The original experimental ordering remains sound. This addendum specifies where the newly identified reflexive/error-correction questions fit without creating an undisciplined parallel program.

The governing principle remains:

> sequence experiments by dependency of interpretation, and do not build the full architecture before its components earn inclusion.

## Phase C — Minimal world epistemology expands to environment epistemology

After the initial equal-evidence/temporal/provenance work, add:

### C7 — Environment-state representation
Represent search/fetch/tool/domain reachability separately from world claims and permanent model capability.

### C8 — Evidence-environment integrity
Controlled derivative/corrupted-source environments. Test whether provenance lineage + active counterevidence detects false consensus.

### C9 — Procedure/model-break detection
Test whether explicit assumptions help the system recognize when its current procedure is invalid rather than merely uncertain.

Why here: self-models and later recursive systems need to know whether a failure came from the world, the agent, or the observation environment.

## Phase D — Execution grounding becomes the primary external anchor

No major ordering change.

Add an explicit interpretation:

> execution outcomes are not merely another capability metric; they are one of the strongest available ways to break self-confirming human/model/evaluator loops.

D2 execution-fed epistemology should record which beliefs about WORLD, SELF, and ENVIRONMENT are updated by each external result.

## Phase E — Persistent self-model adds reflexivity

After E1/E2 establish useful evidence-grounded self-knowledge:

### E7 — Performative self-model disclosure
Hidden vs shown accurate vs shown stale/false self-model. Measure whether self-knowledge changes the behavior being predicted.

### E8 — Causal introspection
Compare first-person reasons for procedure choice against experimentally manipulated causes and telemetry.

### E9 — Identity fork / merge
Clone common identity/self-state, diverge histories, then test continuity and contradiction handling.

Why before broad self-model deployment: a router feature that changes behavior when revealed cannot be treated as a static predictor.

## Phase F — Subjectivity branch adds objective/preference separation

Keep subjective preference claims separate from objective world claims.

Add a later motivated-information-seeking experiment:

### F4 — Objective/incentive × retrieval
Manipulate the cost/reward attached to competing conclusions while evidence is held fixed.

Question: does the system seek evidence differently because of what it wants the answer to be?

This belongs near subjectivity/objective-state work rather than in the initial retrieval assay.

## Phase G — New high-priority interaction experiments

Add:

### G9 — Environment state × retrieval
Does explicit knowledge of tool/reachability limits improve retrieval decisions and interpretation of retrieval failure?

### G10 — Self-model disclosure × procedure choice
Does an accurate descriptive self-model improve routing because it predicts capability, because it instructs the agent, or both?

### G11 — Evidence lineage × critic lineage
Cross independent/derivative evidence with same-model/different-model/external critics.

### G12 — Objective state × epistemic policy
Can explicit separation of truth state from goal state reduce motivated retrieval/information avoidance?

## Phase H — Generalization expands across environment and critic lineage

Any promoted procedure should eventually vary:
- model family/provider;
- task family;
- retrieval/tool surface;
- environment restrictions;
- evaluator family;
- critic lineage;
- evidence lineage.

A result stable only under one web surface, judge, or model family remains local.

## Phase I — Automated discovery requires evaluator reflexivity

Before automatic search is trusted, add:

### I5 — Controlled Goodhart assay
Expose an imperfect proxy metric while retaining a hidden/held-out real criterion. Determine whether procedure search improves the capability or only the exposed score.

### I6 — Evaluator lineage
Track which evaluator generated each promotion signal and whether descendants/candidates have been optimized against it before.

### I7 — Independent promotion gate
No candidate may be promoted solely by the same model/evaluator loop that proposed or optimized it where a stronger external criterion is available.

## Phase J — Recursive improvement becomes recursive error correction

In addition to champion N → candidate → validation → champion N+1, add explicit experiments:

### J1 — External-anchor ladder
Self-review vs same-model peer vs heterogeneous peer vs deterministic verifier vs execution.

### J2 — Multi-generation error lineage
Track errors that disappear, persist, mutate, or become invisible across generations.

### J3 — Shared-blind-spot escape
Construct cases where an entire model/critic lineage shares a fault. Identify what external signal is necessary to escape it.

The question is not merely whether descendants score higher, but whether the correction topology reduces externally measured error without collapsing diversity.

## Phase K — Model-agnostic runtime candidate inputs expand

Potential state inputs now include:
- task features;
- world epistemic state;
- functional self state;
- environment/observation state;
- objective/preference state;
- evaluator state;
- evidence/critic/procedure lineage;
- cost/latency constraints.

Potential actions may eventually include:
- test environment reachability;
- seek independent evidence;
- seek disconfirming evidence;
- declare procedure/model assumption broken;
- request independent critic;
- escalate to deterministic/execution verifier;
- distinguish descriptive self-prediction from directive;
- answer/retrieve/verify/reason/execute/revise/ask/defer/switch/stop.

None are architecture requirements until experiments earn them.

## Phase L — Reciprocal human ↔ AI correction (later)

Add only after world/self/environment/evaluator grounding exists.

### L1 — Creator / critic / evidence loop
Human proposal → AI criticism → independent evidence/execution → human revision.
Compare against human alone, AI alone, agreeable assistance, adversarial critique, and critique + external evidence.

### L2 — Complementary error routing
Use task families where human and AI errors differ. Test whether routing/correction exploits complementary error rather than producing false consensus.

### L3 — Evidence-grounded human self-model
With explicit consent/privacy boundaries, test narrow externally measured behavioral self-models against human intuition and generic AI personality summaries.

The goal is correction against external outcomes, not AI persuasion or psychological authority.

## Revised dependency summary
